### Overview

Spike deliverable for COR-516: autosave the Launch-from-Design page so a product stakeholder can decide whether to adopt the pattern (yes → polish and cancel a related product ticket; no → carry forward there).

The page already had diff/dirty/save machinery; this is mostly a *trigger* change plus folding content-title rename into one visible "saved" signal.

Design is a **hybrid**: fields autosave on blur, and the toolbar status indicator doubles as a **manual-save button** (enabled only when there are unsaved changes or a save failed). The button covers states autosave-on-blur cannot reach — most importantly **adding content**, which has no field blur — and gives a fallback for reviewer peace of mind.

**Why blur, not debounce:** debounced autosave of config/text fields is a documented platform anti-pattern. Blur matches the content-title save already on this page.

### Changes

- Replace the manual **Save Changes** button with **autosave on blur** for About/Sampling text fields (Enter in a textarea stays a newline)
- Add a reusable save-status indicator in the toolbar that is both a status readout and a button: **Saving… / Saved / Modified / Failed to save**. Clickable only when Modified or Failed; disabled while Saving or once Saved
- Fold per-content **title rename** into that one indicator via a generic `save-status` event (including a `retry` callback so a failed rename can be retried from the indicator)
- Drop the post-save refetch; advance the local server baseline to exactly what was sent, so edits made during an in-flight save are not clobbered
- Add an autosave flush loop that picks up trailing edits made mid-save
- Stop gating inputs on saving so a slow save does not block the next field

### Testing (sanitized)

- Unit coverage for baseline-advance (no refetch), in-flight edits not clobbered, and flush of trailing edits
- Page specs for indicator props, indicator-triggered autosave, field-blur autosave, and content-rename status (in-flight + failure→retry)
- Content-editor card specs for `save-status` emissions and retry
- Cypress launch specs updated to use the status indicator instead of the removed Save Changes button
- Full UI unit suite green aside from pre-existing skips; lint clean

### Quality Assurance (sanitized checklist)

- Edit title / description / special instructions → blur → toolbar **Modified → Saving… → Saved**
- Add a content item → indicator shows **Modified** → click to save (no blur path)
- Rename a content item → same **Saved** confirmation
- Reload → edits persisted; reopen draft → values hydrate and keep autosaving
- Toggle sampling type → autosaves; toggling back restores the custom note in-session
- Failure case (offline): blur → **Failed to save**; click indicator to retry once online

### Deferred (non-blocking)

- Root-cause clobber instead of baseline-advance workaround
- Concurrent saves with different values currently return the in-flight promise and can drop later values
