### Overview

Wires a new quiz item type for text-span annotation into the quiz: a wrapper sources article markdown and the interview's highlights, forwards highlight saves to the interview API, and gates Continue on the respondent reaching the end of the article.

Every highlight event is one interaction type (last-write-wins upsert keyed by a client-minted id), nested under a single highlight input field on the API. There is no delete (feature dropped by design). A server-owned content identifier is stamped from the treatment on each save for data lineage and is never sent or read by the client. An interview's treatment is fixed at creation, so its highlights always belong to its one article; earlier acceptance criteria that filtered by content id were retracted during review.

The presentational highlighter component initially ships as an inert placeholder so the wrapper imports cleanly; a follow-on ticket replaces it with the real selection/comment UX and scroll detection. The stub emits `update:canContinue` true on mount so quizzes stay passable until then.

Merges to a feature integration branch paired with the API service. CI pairs sibling repos by head branch name, so a mirror branch on the API repo is required until merge; without it the quiz end-to-end job falls back to API `main`, which lacks the read fields.

### Changes

- Quiz constants — add item type and interaction type for text-span highlight save
- Quiz wizard — render the annotation quiz-item wrapper for the new item type
- New quiz-item wrapper — sources markdown from the item, passes interview highlights into the component, feeds save/blur events into the same store upsert, and forwards continue-gate updates. Saves are stripped to the declared input fields; an unknown field (for example GraphQL `__typename` on a rehydrated highlight) is rejected by the API and would permanently wedge the store's serial update queue
- Quiz store — select highlights on interview find-or-create; carry nested highlight on update; optimistic save via the existing serial execution queue; session-local Continue gate folded into page/finish/submit helpers. A respondent already past the article page stays ungated across reload (page index survives in session storage; the scroll flag does not)
- Demo quiz store — same action surface, local state only; scroll gate not enforced in demo
- Interview update composition — upsert by id; blank comment clears; missing/null comment leaves the stored comment untouched
